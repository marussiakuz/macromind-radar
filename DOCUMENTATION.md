# Настройка и работа с TechTrendSearcher

Первый запуск описан в [README](README.md). Здесь — дополнительные настройки и способы проверить установку.

## Режимы работы

| Режим | Что происходит | Что требуется |
| --- | --- | --- |
| Демонстрация (`RADAR_DEMO=1`) | Открывается сохранённый разбор Edge | Только приложение; ключи не нужны |
| Новый анализ (`RADAR_DEMO=0`) | Поиск источников, извлечение, проверка и сборка карточек | Поисковый API, сервер модели и разрешённый бюджет |
| Тесты и fixtures | Код работает с подготовленными ответами | Зависимости Python; платных запросов нет |

В деморежиме нельзя получить новый ответ на произвольную тему. Если готового разбора нет, сервис сообщает об этом и не запускает пересчёт. Версия сохранённого примера может отличаться от текущей версии конвейера.

В рабочем режиме повторно используются только совместимые результаты. При смене модели, её сервера или настроек поиска старый результат может потребовать нового анализа. Один и тот же активный запрос возвращает уже созданную задачу.

## Настройки

Скопируйте `.env.example` в `.env` **в корне репозитория**. После изменения переменных перезапустите контейнер:

```bash
docker compose up -d --force-recreate
```

Не добавляйте `.env` в Git. При запуске Python без Docker приоритет настроек такой: переменные процесса, корневой `.env`, затем `hackathon/.env` для совместимости со старой установкой. Чтобы избежать путаницы, используйте один корневой файл.

| Переменная | Назначение |
| --- | --- |
| `RADAR_DEMO` | `1` — только сохранённые разборы; `0` — новый анализ |
| `RADAR_PORT` | Порт локального Docker-сервиса, по умолчанию `8000` |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | Доступ к веб-поиску Yandex |
| `OPENALEX_API_KEY` | Поиск научных публикаций через OpenAlex |
| `RADAR_LLM_URL` | Полный URL метода `/v1/chat/completions` |
| `RADAR_MODEL` | Имя модели у выбранного провайдера |
| `RADAR_LLM_API_KEY` | Отдельный ключ модели; без ключа допустим локальный сервер |
| `RADAR_LLM_TIMEOUT_S` | Тайм-аут ожидания ответа модели, по умолчанию 90 секунд; увеличьте для медленного сервера |
| `RADAR_LLM_AUTH_SCHEME` | Схема авторизации; автоматически `Api-Key` для Yandex и `Bearer` для остальных |
| `RADAR_LLM_REASONING_EFFORT` | Необязательный параметр модели; по умолчанию `none` для Yandex, для других не отправляется |
| `RADAR_EXTRACTION_PACKETS` | Максимум пакетов извлечения, по умолчанию `200` |
| `RADAR_MAX_PER_SOURCE` | Ограничение документов одного источника, по умолчанию `999` |
| `RADAR_MIN_PUBLISHED` | Нижняя граница даты публикации: `2024-01-01`; пустое значение отключает фильтр |
| `RADAR_RUN_DEADLINE_S` | Срок этапа построения пула, по умолчанию `3600` секунд; не включает все дальнейшие проверки |
| `RADAR_RUN_TIMEOUT` | Через сколько секунд показать предупреждение о долгой задаче; поток продолжает работу |
| `RADAR_DAILY_RUNS`, `RADAR_IP_DAILY_RUNS` | Суточное число новых запусков всего и с одного IP |
| `RADAR_PUBLIC_TOKEN` | Необязательный токен для запуска анализа через интерфейс или API |
| `RADAR_CORS_ORIGINS` | Разрешённые адреса отдельного интерфейса через запятую |

Документы без установленной даты не отбрасываются. Ограничение загрузок и число пакетов извлечения — разные величины: из одного длинного документа могут извлекаться несколько пакетов. Уменьшение лимитов удешевляет работу, но может снизить полноту.

## Своя модель

Приложение отправляет обычный запрос Chat Completions с полями `model`, `messages`, `temperature` и `max_tokens`. Ожидается текст в `choices[0].message.content`; внутри текста большинство этапов ждёт JSON. Streaming, tools и изображения для этого подключения не требуются.

### Ollama на компьютере с приложением

Сначала установите и запустите Ollama, загрузите выбранную модель и убедитесь, что она отвечает. В `.env` приложения:

```dotenv
RADAR_DEMO=0
RADAR_LLM_URL=http://host.docker.internal:11434/v1/chat/completions
RADAR_MODEL=your-installed-model
RADAR_LLM_API_KEY=
RADAR_PRICE_INPUT_MTOK=0
RADAR_PRICE_OUTPUT_MTOK=0
RADAR_RUN_COST_LLM=0
```

`host.docker.internal` означает компьютер, на котором запущен Docker. Это не адрес другого контейнера. Сервер модели должен принимать соединения из Docker; при необходимости настройте адрес прослушивания и доступ в локальной сети. Не открывайте сервер модели всему интернету. Без Docker замените имя хоста на `127.0.0.1`.

В модели должен быть настроен достаточный контекст для системной инструкции и нескольких фрагментов документов. Начните с 16–32 тысяч токенов и проверьте реальные запросы; это ориентир, а не гарантия для любого документа. Длинные ответы только в `reasoning_content` не подходят: приложение ждёт итоговый текст в `content`. Параметры reasoning зависят от модели.

Подробности API и настройки контекста: [документация Ollama](https://docs.ollama.com/api/openai-compatibility).

### Удалённый сервер или vLLM

```dotenv
RADAR_LLM_URL=https://model.example.org/v1/chat/completions
RADAR_MODEL=your-served-model-name
RADAR_LLM_API_KEY=your-model-api-key
RADAR_LLM_AUTH_SCHEME=Bearer
```

Адрес и имя выше — образец, замените их реальными. Сервер сам загружает веса модели; приложение не устанавливает и не дообучает её. Для vLLM нужен настроенный шаблон диалога выбранной модели: [документация сервера](https://docs.vllm.ai/en/latest/serving/openai_compatible_server/).

Для платного сервера укажите его цены в `RADAR_PRICE_INPUT_MTOK` и `RADAR_PRICE_OUTPUT_MTOK` — рубли за миллион токенов. Ключ Yandex используется только для Yandex и не пересылается стороннему серверу модели.

### Проверка подключения

После изменения `.env` выполните `docker compose up -d --force-recreate`. В `/api/health` отображается имя выбранной модели, но эта проверка **не делает вызов к ней**. Для проверки полного анализа задайте лимиты и запустите конкретный запрос через интерфейс. Это может обращаться к платным API.

Тесты репозитория проверяют формат запроса, авторизацию, кэш и учёт расходов с подменённым HTTP-ответом. Они не подтверждают качество любой подключённой модели. При смене модели сравните несколько результатов вручную: корректность цитат, JSON, связь с темой, объединение дублей и причины исключений.

## Расходы

У поиска и модели отдельные лимиты. Перед API-вызовом приложение резервирует расчётную сумму. После ответа модели сумма уточняется по полю `usage`; при ошибке или неизвестном расходе резерв сохраняется. Это консервативная внутренняя оценка, а не точная выписка провайдера. Тарифы и токенизация могут отличаться; дополнительно используйте лимиты в кабинете провайдера.

```bash
docker compose exec radar python -m radar.ledger status
docker compose exec radar python -m radar.ledger topup \
  --id pilot-02 --search 100 --llm 300 --reason "Следующий этап проверки"
```

Каждый новый `--id` добавляет указанные суммы и задаёт предел расходов следующего этапа. Старые остатки остаются в журнале, но не увеличивают лимит этого этапа. Повтор того же идентификатора с теми же суммами ничего не добавляет; с другими суммами вызывает ошибку. Указывайте обе суммы: значение `0` запрещает новые платные вызовы в этой категории на текущем этапе.

Для бесплатной локальной модели задайте нулевые тарифы токенов, `RADAR_RUN_COST_LLM=0`, а в команде пополнения — `--llm 0`.

`RADAR_RUN_COST_SEARCH` и `RADAR_RUN_COST_LLM` — минимальные остатки для старта, по умолчанию 60 и 200 ₽. Это предварительная проверка, а не обещание цены: итоговый анализ может потребовать больше. Платные вызовы всё равно ограничивает журнал. Если денег недостаточно, часть проверки может остаться незавершённой.

Не удаляйте `ledger.json` действующей установки для восстановления лимита. Для новых разрешённых расходов используйте `topup`. Демонстрационный пример не использует бюджет.

## Разработка без Docker

Нужны Python **3.13**, Node.js **22** и npm. Команды ниже рассчитаны на Linux/macOS; на Windows используйте WSL2 или Docker. Выполняйте их из корня клонированного репозитория.

```bash
cp .env.example .env
python3.13 -m venv hackathon/.venv
source hackathon/.venv/bin/activate
python -m pip install --upgrade pip
```

Для Linux сначала установите CPU-сборку PyTorch, чтобы не загружать CUDA:

```bash
python -m pip install torch==2.10.0 --index-url https://download.pytorch.org/whl/cpu
```

На macOS этот отдельный шаг пропустите. Затем:

```bash
python -m pip install -r hackathon/requirements.txt
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('intfloat/multilingual-e5-small')"
cd tech-trend-searcher
npm ci
VITE_RADAR_API=same-origin npm run build
cd ..
PYTHONPATH=hackathon python -m uvicorn radar.public:app --host 127.0.0.1 --port 8000
```

Откройте http://localhost:8000. В Docker эти шаги делает сборка образа. Модель эмбеддингов используется для сравнения текстов и не является основной языковой моделью. Если она отсутствует, семантическое объединение может пропускаться; для рабочего анализа загрузите её заранее.

Для разработки интерфейса отдельно запустите `npm run dev` из `tech-trend-searcher/` и откройте http://127.0.0.1:5174. В таком режиме Vite по умолчанию обращается к API на порту 8000.

### Проверки без платных API

Из корня, с активированным виртуальным окружением:

```bash
python -m pytest hackathon/radar/tests -q
cd tech-trend-searcher
npm run build
cd ..
PYTHONPATH=hackathon python -m radar run --direction "Защита ИИ" --mode fixtures
```

Fixtures — небольшой искусственный набор ответов, который проверяет работу конвейера. Это не оценка точности поиска. Некоторые регрессии дополнительно используют локальные рабочие прогоны, если они есть; приватные файлы не нужны для базового набора тестов.

## API

Интерактивное описание — http://localhost:8000/docs.

| Метод | Назначение |
| --- | --- |
| `GET /api/health` | Состояние сервиса, деморежим, выбранная модель |
| `GET /api/limits` | Расчётный бюджет, квоты, число активных задач |
| `GET /api/runs` | Список сохранённых прогонов |
| `POST /api/search` | Создание задачи по запросу |
| `GET /api/search/{job_id}` | Прогресс, ошибки и готовые карточки |

Демонстрационный запрос:

```bash
curl -X POST http://localhost:8000/api/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"Edge","demo":true}'
```

В ответе придёт `job_id`; подставьте его в `/api/search/{job_id}`. Если настроен токен запуска, добавьте заголовок `x-radar-token`. В интерфейсе для него есть отдельное поле. Токен хранится только в текущей сессии браузера.

## Хранение и ограничения

В Docker рабочие данные лежат в томе `radar-data`, путь внутри контейнера — `/app/radar-runs`. Без Docker — `hackathon/radar-runs`; его можно заменить переменной `RADAR_RUNS_DIR`.

В каталоге прогона сохраняются манифест, документы, кандидаты, диагностические данные и карточки. Действующие задания хранятся в памяти процесса: после перезапуска их прогресс теряется, но записанные результаты и расходы остаются. Запускайте один процесс Uvicorn; несколько workers пока не поддерживаются.

Токен ограничивает запуск, но не делает содержимое сервиса приватным: готовые результаты и API чтения доступны без него. Для закрытого контура используйте отдельную аутентификацию на прокси или сетевое ограничение. Не размещайте конфиденциальные материалы на открытом демонстрационном сервере.

HTML и текстовые PDF поддерживаются. OCR сканов, авторизация на сайтах и обход платного доступа не реализованы. Недоступные страницы, неустановленные даты, ограничения API и ошибки извлечения уменьшают полноту. Проверка дословности цитаты подтверждает её наличие в документе, но не истинность самого документа.

## Если что-то не запускается

| Проблема | Что проверить |
| --- | --- |
| `Cannot connect to the Docker daemon` | Запустите Docker Desktop или службу Docker Engine |
| Порт 8000 занят | Задайте `RADAR_PORT=8080` в `.env`, пересоздайте контейнер и откройте порт 8080 |
| Первая сборка остановилась | Доступ к npm/PyPI, PyTorch и Hugging Face, свободное место и память Docker |
| По теме нет сохранённого разбора | В деморежиме откройте Edge; для новой темы включите рабочий режим |
| `401` | Токен запуска в интерфейсе; для ошибки внутри анализа — ключ и права API |
| `402` или сообщение о лимите | `python -m radar.ledger status` внутри контейнера, затем разрешённое пополнение |
| `429` | Суточная квота приложения или ограничение внешнего провайдера |
| Модель не отвечает | Полный URL, имя модели, доступ из контейнера, авторизация, поддерживаемые параметры |
| Ответ содержит только reasoning | Настройка reasoning модели; приложение ожидает финальный `content` |
| Статика работает, `/api/health` нет | Адрес API; отдельно размещённому интерфейсу нужен `VITE_RADAR_API` при сборке |

Журнал: `docker compose logs --tail=100 radar`. Перед передачей журнала удалите ключи и другие закрытые данные, если добавляли их в собственные диагностические сообщения.

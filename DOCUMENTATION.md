## 1. Задача и критерий приёмки

Заказчик просит по введённому технологическому направлению выдать до 15 зарождающихся
научно-технологических трендов: что это, какую проблему решает, в чём преимущество,
кейс-пример и источник. Обязательно показать методологию определения «зарождающегося».

Из уточнений заказчика, определяющих устройство решения:

1. Эксперты голосуют **по каждой позиции** отдельно, порог согласия не ниже 75 %.
2. Проверка идёт **открытым запросом**, в том числе по направлениям вне их таблицы.
3. Технологии отбраковывались «по уже большому количеству инвестиций, упоминаний и компаний».
4. Их список построен на **цикле хайпа Гартнера** — интересует точка innovation trigger.
5. Выдавать меньше пятнадцати позиций допускается.
6. Список отбракованного — плюс; наличие ETL — плюс.
7. Ответ на запрос за 20 минут; на защите попросят живой запуск.

Отсюда два следствия, определившие архитектуру. Первое: оптимизируем **защитимость
отдельной позиции**, а не длину списка. Второе: число компаний и упоминаний — признак с
двумя концами, поэтому оно работает и на повышение (категория формируется), и на
отбраковку (категория уже мейнстрим).

## 2. Стек

| Слой | Технологии | Почему так |
|---|---|---|
| Сервис | Python 3.13, FastAPI, uvicorn, pydantic | синхронный конвейер с длинными задачами; задачи выполняются в потоках, состояние опрашивается по HTTP |
| Загрузка | httpx, lxml, pypdf | параллельная загрузка с замком на владельца, соблюдение robots.txt, запрет приватных адресов, разбор HTML и PDF |
| Поиск | Yandex Search API, OpenAlex, Hacker News Algolia | платный веб-поиск, бесплатная научная база, бесплатный поиск по сообществу разработчиков |
| Модель | Qwen3.6-35B через Yandex AI Studio | извлечение кандидатов, канонизация термина, проверка области, аудит доказательств |
| Векторы | sentence-transformers, `intfloat/multilingual-e5-small`, numpy, scikit-learn | локально на процессоре, без сети и без оплаты: сопоставление и объединение |
| Интерфейс | React 19, TypeScript, Vite | существующее приложение в стилистике банка |

Дообучение моделей и GPU не используются. Это измеренное решение, а не экономия: на
доступных объёмах разметки (23 позиции с градуированными оценками, человеческих ноль)
обучение не дало прироста выше полосы шума. Подробности в разделе 7.

## 3. Конвейер: десять шагов

### 3.1 Привратник запроса

Аналитик может ввести что угодно, а полный прогон стоит около 90 ₽ и пятнадцать минут.
Поэтому запрос сначала проверяется двумя поисковыми вызовами (около 1 ₽) и локальной
кластеризацией выдачи. Три случая ловятся надёжно:

- **запрос понят как товар или слово**: по запросу «Edge» 15 страниц из 18 крупнейшей
  группы — скачивание браузера Microsoft Edge и словарный перевод. Сервис отвечает за
  16 секунд и объясняет, что нужно назвать область;
- **два смысла**: две группы выдачи по четверти и более при низкой близости центров;
- **нет материала**: меньше шести страниц или меньше четырёх сайтов.

Широту запроса автоматически определить не удалось, и это измерено: три способа (кластеры
затравочной выдачи, повтор лексики запроса, расхождение плана с запросом по векторам) либо
бракуют законные узкие запросы, либо дают зазор 0,04 при диапазоне модели 0,78–0,88. Поэтому
на односложном запросе сервис **показывает план** и просит подтверждение: человек видит
подмену темы сразу — на запросе «технологии» планировщик выдал ветви про безопасность
ИИ-агентов. Решение всегда остаётся за аналитиком: запрос можно запустить принудительно.

### 3.2 Дерево поиска

Корень — запрос аналитика. Ветви строятся по двум осям одновременно:

- **боли**: нерешённые проблемы области, сформулированные из свежей выдачи и научных работ
  («платёж, инициированный автономным агентом, нечем авторизовать»);
- **предметы и слои**: инструменты и активы, слои инфраструктуры включая криптографические
  примитивы, каналы взаимодействия включая голос, функции отрасли включая взыскание, объекты
  надзора.

Вторая ось добавлена по измерению: план из одних болей не покрыл шесть категорий заказчика из
семнадцати по «Финтеху», и все шесть — предметы, а не проблемы (паи денежных фондов,
депозитные токены, постквантовая криптография). У предмета нет боли, о нём так не спросишь.
После добавления оси нашлись ещё три категории, включая постквантовую криптографию.

Планировщик заземлён на свежих источниках, а не на памяти модели: без заземления он дважды
выдавал таксономию из обзоров и давал нулевое покрытие.

### 3.3 Поиск и отбор адресов

36 запросов по ветвям и линзам (product, funding, standard, research, pilot, fix), до 160
уникальных адресов в очереди загрузки. Отбор адресов **круговой**: по одному результату с
каждого запроса по кругу. Измерено: при отборе «первые подходящие до квоты» 64 места занимали
результаты 7 запросов из 24, круговой отбор поднял до 34 из 36.

### 3.4 Загрузка

Параллельно, 8 потоков, с замком на владельца: к одному сайту обращения идут по очереди с
задержкой. Соблюдается robots.txt, запрещены приватные адреса, есть дедлайн. Разбираются HTML
и PDF; у PDF склеиваются строки, разорванные вёрсткой, и отрезается обложка с выходными
данными. Без склейки цитата не находится в тексте и кандидат отбраковывается — то есть PDF
давали бы документы и ноль пригодных кандидатов.

Пределы загрузки и извлечения разведены: загрузка бесплатна, извлечение платно. На извлечение
отбираются 72 документа **по разнообразию** запросов и хостов, а не первые по порядку.

### 3.5 Извлечение

Каждый кандидат — это **механизм × объект × применение** плюс дословная цитата. Цитата
обязана быть подстрокой сохранённого снимка страницы; это проверяется программно, а не
доверяется модели. Кандидат без проверенной цитаты не допускается дальше.

### 3.6 Окно зрелости

Три измеряемых оси: возраст первого упоминания термина, общее число упоминаний, доля
упоминаний за последний год. Всё нормировано на **скорость обновления самой области**: разброс
базовой скорости между областями пятикратный, единый порог отбраковал бы медленные области
целиком. Границы выведены из распределения 33 эталонных категорий: медиана упоминаний 3,
p90 = 423, медианная доля свежих работ 47 %.

Термин для измерения берётся из цитаты автора, а не из нашего пересказа: 126 кандидатов из 180
получали ноль находок, потому что мы искали русский пересказ в англоязычном индексе.

Если термин в индексах не измерился, позиция не отбрасывается: считаются признаки, видимые в
самом источнике — назван орган стандартизации или регулятор, названы две и более организации,
есть датированное событие за последние 24 месяца, найдены независимые реализаторы.

### 3.7 Исключение доказанно зрелого

Правило `proven-maturity/3`. Исключить как зрелое можно **только** при положительно доказанном
массовом применении. Три отдельных вопроса к модели:

1. предложить факты применения (массовое повседневное использование либо состоявшееся
   регулярное коммерческое использование у покупателя);
2. независимо проверить каждый факт по цитатам: та же область, состоявшееся использование,
   подтверждённые даты, буквально названные организации, корректная роль источника;
3. отдельно проверить границу массовости: единица внедрения (организации, а не сайты и не
   детекции доменов), нижняя численная граница, дословный фрагмент о множестве организаций.

Дословные проверки, каждая из которых ловит реальную ошибку: имя организации обязано стоять в
цитате; `minimum_count` обязан быть целым числом, а не строкой; фрагмент о широте обязан быть
подстрокой процитированного окна; счётчик доменов не равен организациям; дата события не может
быть позже среза. Разделение на три вопроса нужно потому, что один общий вопрос модель
проходит по авторитету источника: один автор, убравший функцию с личного сайта, был признан
массовым применением категории.

Составной маршрут: три независимых поставщика, два покупателя, два владельца источников и
документированный год повторного применения.

### 3.8 Исключение доказанно опровергнутого

Правило `proven-refutation/1`. Три основания: источник сам объявляет объект вымыслом;
единственная реализация, на которой держится кандидат, отозвана; компетентный источник
опровергает именно этот механизм при тех же условиях. Отсутствие продукта, инвесторов и
публикаций, ранняя стадия, прототип, дороговизна и неизвестная стадия фантастикой **не**
являются: это признаки настоящего слабого сигнала.

Обе корзины исключений раздельны и обратимы. У каждого решения сохраняются основание, цитаты,
версия правила, отпечаток досье и срез. Изменилось досье, срез или правило — решение
пересчитывается. Неизвестное остаётся, и остаток называется **кандидатами**, а не
подтверждёнными сигналами.

### 3.9 Объединение эквивалентных

Векторы **предлагают** пары (порог косинуса 0,90), решение принимает проверка: совпадает
объект применения и совпадают признаки семьи технологии (15 групп: фотонный, аналоговый,
цифровой, нейроморфный, в памяти, в пикселе, квантовый, NPU, доверенная среда, федеративный,
LoRA против LoRaWAN, SLM, спекулятивный, событийный). Транзитивности нет: A≈B и B≈C не
объединяют A и C.

Правило признаков семьи введено по измерению: порог 0,90 слил «фотонные нейроморфные схемы» с
аналоговой VLSI-архитектурой, а «интеграцию ускорителей в микроконтроллеры» — с аппаратными
корнями доверия. Обе поглощённые записи соответствуют категориям заказчика, то есть склейка
уничтожала узкую категорию.

### 3.10 Доказательная папка и ранжирование

По каждой верхней позиции собирается то, чем таблица заказчика описывает свои строки:
компании с ролями (разрабатывает, внедряет, исследует, финансирует, стандартизирует), хроника
датированных событий, раунды с суммой, стадией и ведущим инвестором, список независимых
доменов. Три ограничителя строгости: позиция с доказательствами из одного домена не может быть
уверенным сигналом; раунд принимается только при подтверждённой связи с позицией; дата позже
среза не принимается.

Ранжирование — прозрачная сумма измеренных признаков с расшифровкой каждого слагаемого в
карточке. Обученный реранкер существует, но в продукт не подключён (раздел 7).

## 4. HTTP API

Базовый адрес по умолчанию `http://127.0.0.1:8000`. Интерактивная схема — `/docs` (Swagger UI,
генерируется FastAPI автоматически), машинная — `/openapi.json`.

### `POST /api/search`

Запускает разбор направления. Тело:

```json
{"query": "слабые сигналы в финансовых технологиях", "plan": "mixed", "force": false}
```

- `query` — направление аналитика, не короче трёх символов;
- `plan` — `mixed` (боли и предметы, по умолчанию), `pains`, `segments`;
- `force` — запустить, несмотря на замечание привратника.

Ответ: `{"job_id": "…", "demo": false}`. Задача выполняется в фоне.

### `GET /api/search/{job_id}`

Состояние задачи. Ключевые поля:

| Поле | Смысл |
|---|---|
| `status` | `running`, `completed`, `failed`, `needs_query_fix` |
| `stage` | текущий шаг конвейера по-русски |
| `cached` | найден сохранённый пул документов по этому запросу |
| `cards_from_cache` | показан сохранённый разбор: ничего не пересчитывалось и не потрачено |
| `gate` | вердикт привратника: статус, объяснение, чтения запроса, предложения |
| `trends` | до 15 позиций (структура ниже) |
| `rejected`, `rejected_total` | отбракованное с причинами |
| `filters` | сводка доказательных фильтров: сколько исключено, сколько не проверено, версии правил |
| `funnel` | воронка прогона: запросы, находки, адреса, документы, кандидаты, стоимость |
| `confident`, `needs_review`, `merged_duplicates` | счётчики выдачи |

Позиция (`trends[]`): `name`, `definition`, `signal` и `scoreMax`, `tier` (`signal` или
`review`), `verdict`, `reasons[]` — признаки ранней стадии, `sources[]` с дословной цитатой и
датой публикации, `players[]` с ролью и цитатой, `rounds[]`, `chronology[]`,
`independentDomains[]`, `features` — числовые признаки.

### `GET /api/runs`

Сохранённые прогоны: идентификатор, запрос, область, стоимость, время завершения.

### `GET /api/health`

`{"ok": true, "demo": false, "runs": 23}`.

### Режим демонстрации

`RADAR_DEMO=1` — сервис отдаёт только сохранённые разборы и честно сообщает об этом. Нужен
для показа без сети и без расходов.

## 5. Развёртывание

### Локально

Описано в [README](README.md). Коротко: `pip install -r hackathon/requirements.txt`,
`.env` с ключами, `python -m radar.server`, интерфейс `npm run dev`.

### На сервере

Сервис — обычное приложение ASGI, состояние задач в памяти процесса, данные прогонов на диске
в `hackathon/radar-runs/`. Минимальная конфигурация проверена локально и не требует GPU:

```sh
uvicorn radar.server:app --host 0.0.0.0 --port 8000 --workers 1
```

Один рабочий процесс — намеренно: задачи держат состояние в памяти, а расходы считаются через
файл с блокировкой. При нескольких процессах учёт останется корректным (файл блокируется), но
опрос состояния задачи должен попадать в тот же процесс — для нескольких рабочих нужен общий
кеш задач, он не реализован.

Требования: процессор, 2 ГБ памяти под сервис и около 500 МБ под локальную модель векторов,
диск по объёму сохранённых прогонов (один прогон около 20 МБ со снимками страниц).

Интерфейс собирается статикой: `npm run build`, раздача любым веб-сервером. Адрес API
задаётся переменной `VITE_RADAR_API`.

### Публичный MVP: открытый адрес и ограничители

Развёрнут и работает: **https://techtrendsearcher.ru** (Yandex Cloud, 2 vCPU / 4 ГБ / 30 ГБ
SSD, Ubuntu 24.04, Docker + Caddy с сертификатом Let's Encrypt). Страница, API и Swagger
отдаются с одного адреса, поэтому CORS не нужен.

Живой прогон стоит около 90 ₽ и идёт 7–11 минут, поэтому на открытом адресе запускается не
`radar.server`, а `radar.public` — тот же сервис с ограничителями перед первой тратой:

```sh
uvicorn radar.public:app --host 0.0.0.0 --port 8000     # за HTTPS-прокси
```

| Ограничитель | По умолчанию | Что делает |
|---|---|---|
| Бюджет | прогон ≈ 60 ₽ поиска и 30 ₽ модели | новый прогон не запускается, если остатка не хватает на полный: отказ `402` с числами вместо прогона, который умрёт на середине |
| Квота в сутки | 6 всего, 2 с адреса | отказ `429` с текстом причины; сохранённые разборы остаются бесплатными и квоту не тратят |
| Тайм-аут | 20 минут | сторож помечает зависшую задачу отказом, интерфейс перестаёт опрашивать её вечно |
| Токен | выключен | `RADAR_PUBLIC_TOKEN` закрывает **запуск** прогонов, оставляя сохранённые разборы открытыми |

Дополнительный эндпоинт `GET /api/limits` отдаёт остаток корзин, квоту, число активных
задач и тайм-аут. Интерфейс показывает это аналитику **до** запуска: отказ через десять
минут ожидания хуже отказа сразу.

Образ и HTTPS: `hackathon/Dockerfile` (процессорная сборка torch, модель эмбеддингов внутри
образа), `hackathon/docker-compose.yml` (сервис + Caddy с автоматическим сертификатом),
`hackathon/Caddyfile`. Пошаговая инструкция с командами —
[deploy-mvp-2026-09-29.md](hackathon/deploy-mvp-2026-09-29.md).

Ограничители покрыты тестами `hackathon/radar/tests/test_public.py`: короткий запрос,
исчерпанная квота по адресу и общая, нехватка бюджета, бесплатный повтор, токен, снятие
зависшей задачи, сохранение квоты между перезапусками.

### Ключи и безопасность

Ключи только в `.env` или в окружении процесса, в репозиторий не попадают, в логи и артефакты
не печатаются. Загрузчик соблюдает robots.txt, запрещает обращения к приватным адресам,
ограничивает число адресов одного владельца и держит задержку между обращениями к одному
сайту. Документы обрабатываются как данные, а не как инструкции.

---

### Потолки извлечения и отсечка по дате

Загрузка документов бесплатна, платит только чтение моделью: **≈1 ₽ за документ**
(около 4000 входных и 700 выходных токенов). Поэтому пределы разведены: скачиваем широко,
читаем выборочно. Отбор на чтение идёт по одному документу на непредставленный лист
дерева, затем добавками с балансировкой.

Все потолки переопределяются окружением — «полный» режим для проверки покрытия и обычный
для показа не требуют правки кода:

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `RADAR_EXTRACTION_PACKETS` | сколько документов читает модель | 200 (весь корпус) |
| `RADAR_MAX_PER_SOURCE` | сколько документов берём с одного обычного сайта | 999 (снято) |
| `RADAR_RUN_DEADLINE_S` | срок прогона, секунды | 3600 |
| `RADAR_MIN_PUBLISHED` | отсечка по дате публикации, `ГГГГ-ММ-ДД` | 2024-01-01 |

**Откуда порог 2024-01-01.** 29.09.2026 загружены все 283 ссылки из таблицы заказчика;
дата публикации нашлась у 115 (225 страниц ответили, остальные закрыты robots, недоступны
или не разобрались). Самый старый источник — 12.05.2022. По строкам: 76 из 100 имеют хотя
бы одну дату, и `2024-01-01` — единственная граница, при которой **ни одна строка не теряет
все свои датированные источники**. Окно в 24 месяца отсекло бы три строки, включая
«NPU внутри батарейных MCU/SoC»; окно в 12 месяцев — двенадцать.

**Что это стоит.** Полное чтение — 150–160 документов на область вместо 72, то есть
≈150 ₽ модели вместо ≈73 ₽ и 20–30 минут вместо 7–11. Отсечка по дате экономит мало
(6–12 документов на область): дата известна меньше чем у половины корпуса, а
недатированные документы остаются. Для показа профиль возвращается переменными
окружения — например `RADAR_EXTRACTION_PACKETS=72 RADAR_RUN_DEADLINE_S=1200`.

Квота на сайт — про независимость доказательств: три страницы одного вендорского блога это
один голос, а не три подтверждения. Репозитории при этом считаются по работам: каждая
статья arXiv, каждый DOI, каждый репозиторий GitHub и запись OpenAlex — отдельная единица.

**Документы без даты отсечка не трогает.** Дата известна меньше чем у половины корпуса
(29.09.2026 на прогоне Edge — 74 из 161), и отбрасывать недатированные значило бы терять
сигналы, а не старьё. Отсеянные помечаются причиной `older_than_cutoff` в отчёте отбора.

## 6. Учёт расходов

Две раздельные корзины: поиск и модель. Стоимость резервируется **до** обращения к
провайдеру и уточняется по факту; отказ оставляет резерв за собой, потому что провайдер уже
посчитал вызов. История не обнуляется, файл блокируется для нескольких процессов.
Единый источник правды — `hackathon/radar-runs/ledger.json`.

Пополнение записывается явным разрешением с идентификатором — повтор команды сумму не
удвоит, и пополнить можно одну корзину:

```sh
python -m radar.ledger status
python -m radar.ledger topup --id 2026-09-29-llm300 --llm 300 --reason "под публичный MVP"
```

Это обязательный шаг: остаток считается от разрешённых сумм минус расход, поэтому оплату у
провайдера сервис сам не увидит и будет отклонять живые прогоны, пока пополнение не записано.

Тарифы: поиск 0,488 ₽ за вызов; модель 200 ₽ за миллион входных токенов и 300 ₽ за миллион
выходных. Полный прогон направления: **48–90 ₽ и 3–16 минут**. Повторный запрос по
разобранному направлению — 1 секунда и 0 ₽.

## 7. Машинное обучение: что сделано и почему не подключено

В продукте нет обученных весов. Это результат измерений, а не пропуск.

**Реранкер.** Обучен как `silver_experimental` на 23 позициях с градуированными оценками
0–3, источник оценок — агент-аналитик, человеческих подтверждений ноль. Признаки только
числовые: текст исключён намеренно, потому что по аудиту стороннего набора происхождение
данных угадывается по стилю в 64–71 случае из 87, и текстовая модель выучит составителя.

| Вариант | Парная точность | NDCG@15 |
|---|---:|---:|
| текущая прозрачная сумма признаков | 0,680 | 0,601 |
| модель, честная оценка (разбиение по семьям, пары внутри отложенной части) | 0,789 | — |
| контроль на перемешанных метках | 0,632 | — |

Прирост +0,110 при полосе шума ±0,15 на таком размере. Вывод: выигрыш не доказан, модель
остаётся экспериментом. По пути найдена и исправлена утечка в самой процедуре оценки:
первая версия сравнивала отложенную запись с обучающими, и контроль на перемешанных метках
давал 0,746 вместо ожидаемых 0,5.

**Векторы** применяются, но не как поиск: они предлагают пары при объединении и при
сопоставлении с эталоном. Измерено, что полноты поиска они не дают — вектор ищет среди уже
скачанного, отсутствующий документ он не вернёт.

Чего не хватает для настоящего обучения: градуированных **человеческих** оценок на 100+
позициях по областям либо парных сравнений. Единственный масштабируемый источник таких
оценок — действия аналитика в интерфейсе.

## 8. Методология: как измеряем себя

Мы разделяем четыре разные величины и никогда не смешиваем их в одно число:

1. **обоснованные механизмы** — позиция с проверенной цитатой, названной организацией и либо
   датированным событием, либо измерением термина в индексе; инструмент
   `python -m radar.metrics`;
2. **покрытие таблицы заказчика** — сколько её категорий дошло до пула, и отдельно сколько
   сохранилось после каждого фильтра; это наш прокси для отладки, а не критерий приёмки;
3. **попадание в ТОП-15** — в каждой области заказчика 16–17 строк при пятнадцати местах,
   поэтому «все категории в топе» невыполнимо арифметически;
4. **приёмка экспертом** — голоса по каждой позиции; воспроизводится только людьми.

Для сопоставления с таблицей используется ансамбль: лексическое пересечение, локальные
векторы и ключи самой строки. Причина — измерено, что один способ видит 8–9 категорий из 17,
а разные способы видят **разные** категории; ансамбль даёт 11 на том же пуле.

Построчная воронка по всем 100 категориям, с указанием первого места потери для каждой
пропущенной, — `hackathon/reference-funnel-audit-2026-09-29.md`.

## 9. Ограничения решения, названные прямо

1. Доказательные фильтры не исключили ни одной технологии даже в отрицательном контроле
   (Kubernetes, MQTT, TLS 1.3): они работают предохранителем, а сокращение пула до пятнадцати
   делает ранжирование.
2. Проверка принадлежности области несогласована: на Edge помечает 9 позиций из 15, включая
   законные темы. Сортировку по этой метке мы пробовали и откатили по измерению.
3. Три области из шести живьём не прогонялись; в отчётах они помечены «не измерено».
4. Экспертной разметки нет ни по одной позиции; оценки агента-аналитика экспертизой не
   являются.
5. Разброс между повторами одной конфигурации — около двух позиций; улучшения меньше этого
   мы не объявляем улучшениями.
6. Полнота интернета не гарантируется: у нас один платный поисковик и два бесплатных индекса.

# Протокол сравнения двух реализаций фильтра зрелости

Зафиксирован 27.09.2026 **до** того, как любая из сторон увидела результат другой.
Стороны: Claude (`hackathon/radar/`) и Codex/GPT (`radar-codex/`). Правки вносить только
дописыванием с датой, не переписыванием.

## Вход — один и тот же

`bench/pool-защита-2026-09-27.json`, 180 кандидатов области «Защита ИИ», собранных двумя
повторами конвейера Claude 26.09. sha256 содержимого:
`484a4c5d0777b6094cb332942c510a1960ea341ba5c21fe9ad09f21b0f17f08d`

Формат нейтральный: имя, механизм, объект, контекст, извлечённая стадия, организации,
дата события, цитаты с ссылками, источник. Ничего из оценочных схем ни одной из сторон.
Пул можно только читать. Дополнять его своими кандидатами в этом сравнении нельзя —
иначе сравниваются сборщики, а не фильтры.

## Что делает каждая сторона

Прогоняет **свой** фильтр зрелости и ранжирование, выдаёт до 15 позиций в файл
`bench/top-<сторона>-2026-09-27.json`, формат:

```json
{"top": [{"rank": 1, "id": "AI-042", "score": 9.5,
          "why": ["признак", "признак"], "evidence_quote": "...", "source_url": "..."}],
 "rejected_reasons": {"причина": 12}, "method": "одно-два предложения"}
```

Обязательно: `id` из пула, чтобы позиции сопоставлялись механически. Позиций может быть
меньше пятнадцати — заказчик это разрешает, и осознанный короткий список это решение,
а не недоработка.

## Правила, без которых сравнение недействительно

1. **Пороги не подбирать на этом пуле.** Если порог настраивался по этим 180 кандидатам,
   это надо написать в `method`. Сравнение настроенного с ненастроенным ничего не значит.
2. **Не смотреть чужой результат до публикации своего.** Оба файла кладутся в `bench/`,
   и дальше уже можно читать.
3. **Таблицу заказчика в фильтр не подавать.** Ни названия строк, ни столбцы эксперта.
   Она нужна только на этапе разбора, после того как оба списка готовы.
4. Все замеры — из открытых источников, стоимость и число платных вызовов указать в
   `method`.

## Как сравниваем, когда оба файла готовы

**Слепая разметка.** Списки объединяются, перемешиваются с фиксированным зерном,
принадлежность скрывается. Каждая позиция размечается по трём вопросам, независимо:

- **ранняя стадия**: есть подтверждение, что технология существует, но массового рынка
  нет — да / нет / спорно;
- **не громкая**: нет признаков большого объёма инвестиций, множества компаний и
  массовых упоминаний — да / нет / спорно;
- **доказана**: цитата дословно подтверждает механизм, ссылка открывается, дата видна —
  да / нет.

Позиция засчитывается, только если все три «да». Это приближение критерия заказчика:
эксперты голосуют по каждой позиции, порог согласия 75 %.

**Метрики, обе на одинаковых правилах:**

- точность: доля засчитанных позиций от выданных;
- ожидаемый процент при экспертном голосовании = точность, посчитанная на первых
  пятнадцати или на всех выданных, если их меньше;
- пересечение списков: сколько одних и тех же `id` выбрали обе стороны независимо.
  Совпадение — сильный довод в пользу позиции, расхождение — предмет разбора.

**Чего сравнение не измеряет:** полноту относительно таблицы заказчика, качество сборки
кандидатов (пул общий), переносимость на другие области, экспертное принятие.

## Дальше

Победившие решения переносятся в общую версию. Разногласия по конкретным позициям
разбираются по цитатам, а не по общей оценке подхода.

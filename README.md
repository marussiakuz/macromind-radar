# Радар слабых технологических сигналов

> Состояние после проверки Codex 29.09: пять областей прошли сквозную сборку,
> по 15 карточек для проверки; экспертные 15/15 и полнота Excel не достигнуты.
> Шестая область остановлена лимитом Qwen. Текущий backend работает по сохранённым
> результатам без расходов. [Полный проверочный отчёт](hackathon/report-codex-completion-2026-09-29.md)
> и [точка продолжения](hackathon/continuation-codex-unified-20260929.md).


Хакатон «Лидеры цифровой трансформации» 2026, задача **Газпромбанк.Тех**: по введённому
технологическому направлению выдать до 15 зарождающихся трендов с мотивацией, кейс-примером
и источником, и показать методологию определения «зарождающегося».

Аналитик вводит направление — «слабые сигналы в финансовых технологиях», «Edge-вычисления и
периферийный ИИ», «Микрофлюидный чип». Сервис ищет по открытым источникам и возвращает
технологические категории **на ранней стадии**: публикации, первые продукты или стандарты уже
есть, массового рынка ещё нет. К каждой позиции — дословная цитата с ссылкой, компании с
ролями, хроника датированных событий, раунды финансирования и перечень признаков, по которым
позиция признана слабым сигналом. Отдельно выдаётся список отбракованного с причинами.

Критерий приёмки заказчика: эксперты голосуют **по каждой позиции** отдельно, порог согласия
75 %, проверка идёт открытым запросом, в том числе вне их таблицы. Поэтому решение
оптимизировано под защитимость отдельной позиции, а не под длину списка: выдавать меньше
пятнадцати позиций условие допускает.

## Быстрый старт

Нужны Python 3.13 и Node 20+.

```sh
# 1. Бэкенд
cd hackathon
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp ../.env.example .env        # вписать свои ключи, см. ниже
.venv/bin/python -m pytest radar/tests -q      # на 29.09 — 102 passed, сеть не нужна
.venv/bin/python -m radar.server               # сервис на 127.0.0.1:8000

# 2. Интерфейс, в другом окне
cd tech-trend-searcher
npm install && npm run dev                     # адрес печатается в консоль
```

Ключи в `.env` (в репозиторий они не попадают, см. `.gitignore`):

```
YANDEX_API_KEY=...        # Yandex Search API и AI Studio
YANDEX_FOLDER_ID=...
OPENALEX_API_KEY=...      # необязательно: без него научная линза отключается
```

**Без ключей** сервис запускается и отдаёт сохранённые разборы, интерфейс работает на
выгруженных данных и честно об этом сообщает. Тесты проходят полностью: они не ходят в сеть.

### Публичный запуск: тот же сервис с ограничителями

На открытом адресе живой прогон могут запустить посторонние, а он стоит около 90 ₽ и идёт
7–11 минут. Поэтому публично запускается `radar.public` — тот же сервис, но с проверками до
первой траты:

```sh
uvicorn radar.public:app --host 0.0.0.0 --port 8000      # за HTTPS-прокси
docker compose up -d --build                             # или сразу образом, вместе с Caddy
```

Квота (6 прогонов в сутки, 2 с одного адреса), отказ при нехватке бюджета, тайм-аут прогона
и `GET /api/limits` с остатком корзин. Повтор уже посчитанного запроса бесплатен и квоту не
тратит. Пошагово — [deploy-mvp-2026-09-29.md](hackathon/deploy-mvp-2026-09-29.md).

### Проверить работу без сети и без денег

```sh
cd hackathon
.venv/bin/python -m pytest radar/tests -q                                  # все тесты, на 29.09 их 102
.venv/bin/python -m radar.metrics --cards samples/edge-20260928/cards.json # метрика выдачи
```

В `hackathon/samples/edge-20260928/` лежит настоящий прогон по направлению Edge: 135
кандидатов, 15 итоговых позиций, манифест с воронкой и стоимостью.

## Как работает конвейер

```
запрос аналитика
   │
   ├─ 1. привратник запроса ─────────► «уточните»: запрос понят как товар, распадается
   │      2 поисковых вызова (~1 ₽)     на два смысла или не даёт материала
   │
   ├─ 2. дерево поиска: боли области + предметы и слои (инструменты, инфраструктура,
   │      каналы, функции, объекты надзора) → 36 запросов по ветвям
   │
   ├─ 3. загрузка 160 адресов параллельно (robots, задержка на владельца, PDF),
   │      отбор 72 документов на извлечение по разнообразию запросов и хостов
   │
   ├─ 4. извлечение кандидатов: механизм × объект × применение + дословная цитата,
   │      проверяемая как подстрока сохранённого снимка
   │
   ├─ 5. окно зрелости: возраст термина, громкость, доля свежего — относительно
   │      скорости обновления самой области
   │
   ├─ 6. исключение доказанно зрелого (proven-maturity/3)
   ├─ 7. исключение доказанно опровергнутого (proven-refutation/1)
   │      ↑ только по положительным доказательствам; неизвестное остаётся
   │
   ├─ 8. объединение эквивалентных: векторы предлагают, решают объект и признаки семьи
   ├─ 9. доказательная папка: компании с ролями, хроника, раунды, независимые домены
   └─ 10. ранжирование и ТОП-15 + список отбракованного с причинами
```

Подробное описание каждого шага, форматы данных и API — в [ДОКУМЕНТАЦИИ](DOCUMENTATION.md).

## Честный статус

Что измерено и проверяется тестами:

- конвейер проходит целиком; на направлении Edge — 136 документов, 135 кандидатов,
  15 позиций, 193 с поиска и 480 с полного разбора;
- повторный запрос по разобранному направлению отдаётся за секунду и бесплатно;
- дословность цитат проверяется программно: 100 % позиций в проверенных прогонах;
- доказательные фильтры не теряют найденные категории заказчика (сохранность 100 % на
  проверенной выборке).

Что **не** достигнуто и заявлено честно:

- покрытие таблицы заказчика: «Финтех» 16 строк из 17 попадают в пул по всем прогонам,
  Edge 11 из 16 в одном прогоне; три области из шести живьём не прогонялись;
- доказательные фильтры не исключили ни одной технологии даже в отрицательном контроле
  (Kubernetes, MQTT, TLS 1.3) — они работают предохранителем, а сокращение пула делает
  ранжирование;
- обученный реранкер в продукт не подключён: прирост не превысил полосу шума;
- человеческой экспертной разметки нет ни по одной позиции.

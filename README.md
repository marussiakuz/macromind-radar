# Радар слабых сигналов

Пользователь вводит технологическое направление — «защита ИИ», «финтех», «биотехнологии
и генетика», «микрофлюидный чип». Система ищет по открытым источникам и возвращает
технологические категории **на ранней стадии**: о них уже есть публикации, первые
продукты или стандарты, но массового рынка ещё нет. К каждой — дословная цитата с датой
и ссылкой, плюс признаки, по которым она признана слабым сигналом.

Задача хакатона ЛЦТ-2026 от Газпромбанк.Тех. Приёмка: несколько экспертов голосуют по
каждой позиции «слабый сигнал / не слабый сигнал», нужно согласие не ниже 75 %. То есть
важна **точность выдачи**, а не полнота; выдавать меньше пятнадцати позиций разрешено.

## Быстрый старт

```bash
cd hackathon
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install pytest httpx lxml openpyxl pydantic fastapi uvicorn

cp ../.env.example .env          # вписать свои ключи, см. ниже
.venv/bin/python -m pytest radar/tests/test_radar.py -q      # 37 тестов, без сети

.venv/bin/python -m radar.server                              # API на 127.0.0.1:8000
cd ../tech-trend-searcher && npm install && npm run dev       # интерфейс на 5173
```

Ключи в `hackathon/.env`: `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` (поиск и языковая модель),
`OPENALEX_API_KEY` (бесплатный, получается за минуту на openalex.org/settings/api —
**обязателен**, с февраля 2026 параметр mailto отменён и без ключа приходят 429).

Прогон одной области стоит 55–68 ₽ и занимает 5–12 минут. Повторный запрос с тем же
текстом отдаётся из сохранённого прогона бесплатно.

## Устройство

```
запрос → план по нерешённым проблемам области → поиск (веб + OpenAlex)
      → загрузка и разбор → извлечение кандидатов с цитатами
      → канонический термин → окно зрелости → карточки
```

| модуль | за что отвечает |
|---|---|
| `radar/search.py` | план поиска, линзы, роутер источников, круговой отбор ссылок |
| `radar/fetch.py` | загрузка с защитой от SSRF, robots.txt, разбор HTML |
| `radar/extract.py` | извлечение категорий, проверка цитат на дословность |
| `radar/corroborate.py` | канонический термин из цитаты, подсчёт независимых игроков |
| `radar/rank.py` | окно зрелости: границы выведены из эталона, см. `calibrate.py` |
| `radar/relevance.py` | принадлежность направлению запроса |
| `radar/top.py`, `export_ui.py` | сборка карточек и выгрузка в интерфейс |
| `radar/server.py` | HTTP-сервис: открытый запрос запускает конвейер |
| `radar/judge.py`, `evaluate.py` | измерение качества по эталону заказчика |

Дисциплина, которая соблюдается везде: **цитата проверяется на дословное вхождение в
текст загруженного документа**, инструкции внутри страниц не исполняются, таблица
заказчика не передаётся ни планировщику, ни извлекателю, ни ранжированию — только
оценке качества.

# Просьба о ревизии

Этот раздел — для агентов, которые будут смотреть репозиторий свежим взглядом.
Мы два дня чинили конвейер и уперлись в несколько проблем; ниже они с измерениями и
указанием мест в коде. Помощь нужна именно по ним, а не по общему качеству кода.

## Где мы сейчас, честно

| что | значение |
|---|---|
| совпадений с эталоном, «Защита ИИ» | 7 из 16 (оценка модели-судьи, подтверждённых человеком — 2) |
| совпадений с эталоном, «Финтех» | 7 из 17 |
| разброс между повторами одной конфигурации | 7 и 5 из 16, совпали 4 |
| карточек проходит окно зрелости | 1–7 из 80–180 кандидатов |
| открытый запрос вне таблицы («биотехнологии») | 84 осмысленных кандидата, 1 карточка |

Сработало и подтверждено замером: круговой отбор ссылок (раньше 64 места занимали
результаты 7 запросов из 24, теперь 34 из 36) и планирование по нерешённым проблемам
области вместо её сегментов (на «Финтехе» подняло 2 → 7).

## Проблемы, по убыванию важности

### 1. Каноническое имя технологии — корень почти всего

Окно зрелости измеряет строку. Если строка не является тем, как технологию называют
люди, измерение бессмысленно. Сломалось трижды разными способами:

- искали по русскому пересказу в англоязычных индексах — 126 кандидатов из 180 дали ноль;
- стали брать термин из цитаты — получили **названия продуктов**: «Azure Local»,
  «Foundry Local», «Firewall for AI», «General Analysis» (это компания). У торгового
  имени мало упоминаний по определению, поэтому фильтр предпочитал продукты категориям;
- термины из эталона регуляркой — обрывки: `credentials`, `receipts`, `HTTP 402`.

Сейчас: `radar/corroborate.py`, функция `canonical_terms` — модель берёт термин из
цитаты, проверяется вхождение в цитату и несовпадение с названием организации. Термин
извлекается у ~60 % кандидатов. Написан, но **не подключён**, разбор аббревиатур:
`radar/abbrev.py` (алгоритм Шварца-Хёрст, `MCP → Model Context Protocol`).

Что просим: довести извлечение термина. Подключить `abbrev.py`. Возможно, добавить
связывание с Википедией — статья-категория против статьи-продукта различает их надёжнее
любого правила.

### 2. Измерение зрелости не во всех областях одинаково работает

`radar/rank.py`: два источника, берётся первый ответивший. OpenAlex знает все области,
Hacker News точнее по инструментам разработчиков и **слеп к целым отраслям** — на
биотехе отбраковал 84 кандидата из 84.

Границы выведены из распределения 33 эталонных категорий (`radar/calibrate.py`,
`radar-runs/calibration.json`): медиана упоминаний 3, p90 = 423, медианная доля свежих
работ 47 %. Это калибровка на положительных примерах, заявлять на ней успех нельзя.

Что просим: проверить, что порядок источников не смещает результат по областям.
Рассмотреть подгонку S-кривой по годам вместо порогов (BIMATEM, Lezama-Nicolás 2018).

### 3. «Тихо» и «не нашли» неразличимы на малых числах

Ноль или одно упоминание может означать «технология действительно тихая», «спросили
неверной строкой» или «источник не ответил». Третье состояние отделено
(`Signal.status`), первые два — нет.

Что просим: способ отличать. Правило трёх даёт только границу интервала.

### 4. Уровень обобщения категории

Кандидаты выходят либо шире эталона («Защита от инъекций промптов» — целый класс), либо
уже («валидация по схеме» — приём). Судя по таблице экспертов, правильный уровень — это
то общее, что делают три-четыре независимые компании: у них к каждой строке приложено
3–4 стартапа.

Что просим: собирать категорию снизу из кластера игроков. Половина есть:
`corroborate.py` группирует кандидатов по термину и считает организации, но категория
всё ещё берётся из имени, а не из кластера.

### 5. Ранжируются записи, а не категории

`radar/top.py`: несколько записей об одной технологии могут занять несколько мест в
выдаче. Дедупликация по имени есть, по смыслу — нет.

### 6. Разброс между прогонами

Два прогона одной конфигурации дают 7 и 5 совпадений; пересечение имён кандидатов между
прогонами — Жаккар 0,00–0,05. Часть от живой выдачи, часть от модели.

Что просим: снимки поисковой выдачи, чтобы отделить разброс поиска от разброса модели.

### 7. Судья мягче человека втрое

`radar/judge.py` — модель-судья для измерения качества. Из девяти пар, которые она
приняла, независимая слепая проверка подтвердила две-три. Экспертной панели у нас нет.

Что просим: детерминированные правила-лабелеры и согласие двух из трёх вместо одного
судьи.

### 8. Воспроизводимость замеров

Дата среза не фиксируется, старый прогон не повторяется на прежнюю дату. Для отчёта это
важнее, чем для качества.

## Правила, которые просим соблюдать

**Не подавать таблицу заказчика в конвейер.** Ни названия строк, ни объяснения экспертов
— ни планировщику, ни извлекателю, ни ранжированию. Она только для оценки качества.
За два дня мы четырежды случайно нарушили это правило: фикстуры писались по таблице,
примеры уровня обобщения в промпте извлечения были выписаны из неё, перечень тем в
заземлении повторял ненайденные строки, а формулировки пробных запросов брались из
названий категорий. Каждый раз это выглядело как прогресс.

**Цитата обязана дословно находиться в тексте загруженного документа.** Не нашлась —
кандидат не проходит, даже если по смыслу всё сходится. Инструкция в промпте «не
выдумывай» проверкой не является.

**Разделять факт, оценку и предположение.** Замер, который можно повторить командой, —
факт. Расчёт по тарифам — оценка, а не счёт провайдера. Всё остальное — предположение.

**Пороги не подбирать на той же выборке, по которой объявляется улучшение.**

**Перед платным прогоном** — сухой запуск на одном элементе. Один прогон стоит 55–68 ₽,
и мы уже потеряли 26 ₽ на падении в самом конце после выполненной работы.

## Что уже проверено и отвергнуто — не предлагать заново

- **Эмбеддинги и векторный поиск по кандидатам.** Слепая разметка 198 пар: полнота на
  первых пяти одинаковая у лексики, косинуса и гибрида; косинус чаще поднимает
  родительский класс к узкой категории. Отдельная реализация с pgvector прироста не дала.
- **Генерация гипотез моделью с проверкой поиском.** 1 совпадение из 17 против 2 у
  обычного пути: модель регрессирует к штампам отрасли.
- **«Отрицательное пространство»** — строить зрелую таксономию области и брать остаток.
  Опровергнуто дважды на двух корпусах (0 и 1 кандидат): таксономия отрасли по
  построению исчерпывающа, «не укладывается в структуру» отбирает постороннее.
- **Google Custom Search** как замена веб-поиску: режим «по всему интернету» отключён
  Google для новых поисковых систем.
- **Crossref** для подсчёта упоминаний: `query.bibliographic` ищет нестрого, отдаёт
  сотни тысяч результатов на любой запрос.

# TechTrendSearcher

TechTrendSearcher помогает аналитику искать ранние технологические изменения. Вы задаёте направление, сервис собирает материалы из открытых источников, извлекает технологии и готовит до 15 карточек со ссылками, цитатами и пояснениями. Исключённые кандидаты доступны отдельно с причинами.

Это прототип: карточки помогают выбрать темы для проверки, но не заменяют вывод эксперта. Полный охват направления и точность TOP-15 пока не подтверждены независимой разметкой.

## Быстрый запуск у себя

Нужен установленный и запущенный **Docker с Docker Compose v2**. Python, Node.js, ключи API и GPU для просмотра примера не нужны.

```bash
git clone https://github.com/marussiakuz/macromind-radar.git
cd macromind-radar
docker compose up -d --build
```

Откройте **http://localhost:8000** и нажмите **Edge**. В комплект входит сохранённый разбор от 29 сентября 2026 года. В деморежиме новые запросы не выполняются и платные API не вызываются.

Первая сборка требует интернета: Docker загружает зависимости и небольшую модель для сравнения текстов. На это может уйти несколько минут. Для локальной проверки разумно выделить Docker 4 CPU, 8 ГБ RAM и около 10 ГБ свободного диска; это ориентир, а не измеренный минимум.

Проверка и остановка:

```bash
curl http://localhost:8000/api/health
docker compose logs --tail=100 radar
docker compose down
```

Прогоны и учёт расходов хранятся в томе `radar-data` и переживают остановку. Не добавляйте `-v` к `docker compose down`, если хотите сохранить эти данные.

## Новый анализ по своему запросу

1. Скопируйте настройки:

   ```bash
   cp .env.example .env
   ```

2. В `.env` установите `RADAR_DEMO=0`, заполните `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Нужен доступ к Yandex Search API. Для модели по умолчанию тот же ключ должен иметь доступ к Yandex AI Studio; можно задать отдельный `RADAR_LLM_API_KEY`. Для поиска научных публикаций заполните `OPENALEX_API_KEY`.

3. Примените настройки:

   ```bash
   docker compose up -d --force-recreate
   ```

4. Задайте допустимые расходы. Например, до 100 ₽ на поиск и до 300 ₽ на модель для следующего этапа работы:

   ```bash
   docker compose exec radar python -m radar.ledger topup \
     --id first-run --search 100 --llm 300 --reason "Локальная проверка"
   docker compose exec radar python -m radar.ledger status
   ```

Это внутренний лимит приложения, а не пополнение счёта провайдера. Новый журнал начинается с нуля. Повтор команды с тем же `--id` не добавляет деньги второй раз. Для следующего разрешения используйте новый идентификатор и явно задавайте обе суммы.

Введите конкретное направление, например «Периферийные вычисления на микроконтроллерах». Анализ может занять несколько минут и дольше; время и стоимость зависят от документов и модели. Лимит расходов может остановить работу до завершения. Одновременно выполняется один анализ.

## Как использовать свою модель

Код менять не нужно. Нужен сервер с API **Chat Completions**, совместимым с OpenAI. В `.env` укажите полный адрес метода, имя модели на этом сервере и, если требуется, ключ:

```dotenv
RADAR_LLM_URL=http://host.docker.internal:11434/v1/chat/completions
RADAR_MODEL=your-installed-model
RADAR_LLM_API_KEY=
```

`your-installed-model` замените на имя реально установленной модели. Адрес выше подходит для Ollama на том же компьютере, если сервер доступен из контейнера. Для удалённого сервера укажите его адрес. Для запуска приложения без Docker используйте `http://127.0.0.1:11434/v1/chat/completions`.

Если за токены локальной модели платить не нужно, также установите:

```dotenv
RADAR_PRICE_INPUT_MTOK=0
RADAR_PRICE_OUTPUT_MTOK=0
RADAR_RUN_COST_LLM=0
```

Примените изменения командой `docker compose up -d --force-recreate`. Лимит поиска всё равно нужен: подключение своей модели не заменяет поисковый API.

Модель должна выполнять инструкции, возвращать JSON и работать с русскими и английскими текстами. Совместимость API не гарантирует одинаковое качество выдачи. Настройка авторизации, контекста и проверка подключения описаны в [документации](DOCUMENTATION.md#своя-модель).

## Что находится в репозитории

| Путь | Назначение |
| --- | --- |
| `hackathon/radar/` | Python: поиск, обработка документов, анализ и HTTP API |
| `tech-trend-searcher/` | React/TypeScript: интерфейс аналитика |
| `hackathon/samples/` | Сохранённый пример для просмотра без ключей |
| `docker-compose.yml` | Локальный запуск приложения |
| `hackathon/docker-compose.yml` | Дополнение для HTTPS на своём сервере |
| `.env.example` | Настройки API, модели и ограничений |
| `DOCUMENTATION.md` | Настройка, разработка, диагностика и ограничения |

Приватные данные заказчика для запуска не требуются и в репозиторий не включены. Демонстрационные карточки показывают исторический результат, а не свежую проверку всех приведённых утверждений.

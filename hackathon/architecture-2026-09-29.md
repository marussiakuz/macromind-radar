# Архитектура радара слабых сигналов

29.09.2026. Схемы к заявке: конвейер, состав сервисов, поток данных и развёртывание.
Названия на схемах совпадают с именами модулей в `hackathon/radar/`, чтобы схему можно
было читать вместе с кодом.

## 1. Конвейер: от запроса аналитика до ТОП-15

Порядок стадий зафиксирован: фильтры зрелости и опровержения стоят **до** объединения
эквивалентов, объединение — **до** отбора пятнадцати. Обратный порядок уже приводил к
регрессии: склейка после отбора оставляла пустые места в выдаче.

```mermaid
flowchart TD
    Q["Запрос аналитика<br/>открытый текст"] --> G

    G{"gate.py<br/>привратник запроса"}
    G -->|"wrong_sense · ambiguous · no_material"| FIX["Просьба переформулировать<br/>с вариантами уточнения<br/>16 с, ~1 ₽"]
    G -->|ok| PLAN

    PLAN["hypotheses.py<br/>дерево: вершина — запрос,<br/>ветви — сужения области<br/>боли + объекты и слои"]
    PLAN --> SEARCH

    SEARCH["search.py · openalex.py · arxiv.py<br/>36 запросов, 4 линзы:<br/>product · funding · standard · research"]
    SEARCH --> FETCH

    FETCH["fetch.py<br/>загрузка страниц и PDF,<br/>замки по владельцу,<br/>отбор по разнообразию хостов"]
    FETCH --> EXTRACT

    EXTRACT["extract.py<br/>кандидат = термин автора,<br/>механизм, дословная цитата;<br/>цитата проверяется на вхождение<br/>в сохранённый снимок"]
    EXTRACT --> POOL[("Пул кандидатов<br/>135 на прогоне Edge")]

    POOL --> F1["maturity.py<br/>исключить доказанно зрелое:<br/>3 факта массового применения,<br/>независимый аудит каждого факта<br/>+ аудит массовости"]
    F1 --> F2["feasibility.py<br/>исключить доказанно опровергнутое:<br/>прямая фантастика, отозванный<br/>результат, невозможный механизм"]
    F2 --> MERGE["merging.py<br/>склейка эквивалентов:<br/>векторы предлагают (0.90),<br/>правило семейств решает,<br/>транзитивности нет"]
    MERGE --> DOSSIER["dossier.py · players.py · corroborate.py<br/>досье: компании с ролями,<br/>хроника датированных событий,<br/>раунды, независимые подтверждения"]
    DOSSIER --> RANK["rank.py<br/>возраст термина, доля свежих<br/>упоминаний, громкость,<br/>число независимых игроков"]
    RANK --> TOP["top.py<br/>ТОП-15 + список отбракованного<br/>с причиной по каждой позиции"]
```

Неизвестность всегда остаётся в пуле: исключаем только доказанное. Поэтому выдача
называется «кандидаты», а не «подтверждённые сигналы» — фильтры здесь страховка от грубой
ошибки, а не механизм сокращения списка.

## 2. Состав сервисов

```mermaid
flowchart LR
    subgraph UI["Интерфейс · React 19 + TypeScript + Vite"]
        H["Home<br/>запрос"]
        P["Progress<br/>стадии прогона"]
        T["Trends · TrendCard<br/>карточка с цитатой и хроникой"]
        E["Excluded · Candidates<br/>отбраковка с причинами"]
        M["Method<br/>методология и воронка"]
    end

    subgraph API["Сервис · FastAPI, 127.0.0.1:8000"]
        A1["POST /api/search"]
        A2["GET /api/search/:job_id"]
        A3["GET /api/runs"]
        A4["GET /api/health"]
        W["Рабочий поток<br/>pipeline.py"]
    end

    subgraph EXT["Внешние источники"]
        YS["Yandex Search API<br/>платный поиск"]
        YL["Yandex AI Studio<br/>Qwen3.6-35B"]
        OA["OpenAlex"]
        HN["Hacker News Algolia"]
        WWW["Прямая загрузка<br/>HTML и PDF"]
    end

    subgraph DISK["Диск прогона · radar-runs/<run_id>/"]
        R1["raw/ — снимки страниц"]
        R2["hits · fetches · documents · candidates"]
        R3["cards.json · top.json · manifest.json"]
        R4["filter-decisions.json<br/>решения с версией правила<br/>и отпечатком досье"]
        LG["ledger.json<br/>две корзины: поиск и LLM"]
    end

    H --> A1 --> W
    P --> A2
    W --> YS & YL & OA & HN & WWW
    W --> DISK
    A2 --> T & E
    M --- DISK
    W -. "резерв до вызова,<br/>возврат по факту" .- LG
```

Кеш прогонов лежит на диске: повтор того же запроса отвечает за 1 с и 0 ₽, потому что
сохранённые решения привязаны к версии правила и отпечатку досье — при изменении правила
кеш не переиспользуется.

## 3. Развёртывание

Прототип и защита не требуют GPU: локальные векторы `intfloat/multilingual-e5-small`
считаются на процессоре, LLM вызывается по API.

```mermaid
flowchart TB
    subgraph LOCAL["Локальный запуск · ноутбук или стенд"]
        V[".venv, Python 3.13<br/>pip install -r hackathon/requirements.txt"]
        S["python -m radar.server<br/>127.0.0.1:8000 · /docs"]
        N["npm run dev<br/>интерфейс"]
        V --> S
        N -->|"VITE_RADAR_API"| S
    end

    subgraph PAGES["GitHub Pages · статическая витрина"]
        B["npm run build<br/>сохранённый прогон вшит<br/>в сборку (src/generated.ts)"]
        PG["Страница без сервиса:<br/>сохранённый разбор, честная пометка,<br/>инструкция локального запуска"]
        B --> PG
    end

    subgraph KEYS["Секреты"]
        ENV[".env вне репозитория<br/>YANDEX_* , OPENALEX_*"]
    end

    ENV -.-> S
    S -. "python -m radar.export_ui --cards" .-> B
```

Ключи только в `.env` или в окружении: в репозиторий попадает лишь `.env.example` с именами
переменных. Белый список в корневом `.gitignore` устроен так, что по умолчанию не
публикуется ничего, а разрешённое перечислено явно.

## 4. Поток данных одного прогона

Числа — фактический прогон `20260928-194236-edge`, выборка которого лежит в
`hackathon/samples/edge-20260928/`.

```mermaid
flowchart LR
    Q["запрос"] --> QQ["36 запросов<br/>к источникам"]
    QQ --> HH["360 попаданий"]
    HH --> UU["160 уникальных URL"]
    UU --> FF["145 загружено<br/>136 разобрано"]
    FF --> SEL["72 из 136 документов<br/>отобрано на извлечение<br/>по разнообразию"]
    SEL --> CC["135 кандидатов"]
    CC --> MM["135 после склейки"]
    MM --> TT["15 в выдаче<br/>+ 12 отбраковок с причиной"]
```

Стоимость прогона — 89,7 ₽: поиск и извлечение считаются из разных корзин, 13 вызовов
источников были бесплатными.

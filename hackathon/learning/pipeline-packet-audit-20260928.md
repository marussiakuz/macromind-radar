# Аудит пакета кандидатов конвейера: v1 → v2

28.09.2026. Пакет для ручной разметки «weak / mature / unknown» на кандидатах живого
конвейера. Это **стратифицированный диагностический срез**, а не выборка из естественного
распределения потока и не обученный классификатор. По этим 30 карточкам нельзя заявлять
ни долю слабых сигналов в потоке, ни precision@15.

- v1: `learning/pipeline-candidates-20260928/` — сохранён как артефакт, **не размечать**.
- v2: `learning/pipeline-candidates-v2-20260928/` — рабочая версия, новые хеши досье.
- Сборщик: `learning/build_pipeline_packet.py`. Форма: `learning/review-neutral.html`.
- Человеческих меток на момент этого документа: **0**, ни в v1, ни в v2.

## Что исправлено по разбору Codex

### 1. Форма подсказывала класс и не показывала цитату

Подтверждено на диске: в v1 `review.html` перенесён шаблон `reference-review.html`, где
ветка происхождения при `reference_label !== 'weak'` печатает «Кандидат в отрицательные
примеры предложен ИИ…». У всех 30 карточек `reference_label = null`, поэтому подсказка
появлялась **на каждой**. Дословная цитата не выводилась вообще, а подпись под источниками
утверждала обратное тому, что в пакете: «краткие пересказы… а не дословные цитаты».

Сделано: своя форма `learning/review-neutral.html`, а не правка их шаблона. Показывает
область, название, механизм, применение, ссылку, дату публикации или «дата не установлена»,
пересказ и **дословную цитату со смещениями в снимке**. Не показывает никогда: нашу оценку
стадии, балл, уровень `signal`/`review`, происхождение примера, совпадение со строкой
таблицы заказчика, предложение модели.

Модельная стадия убрана и из `concerns`: в v1 там стояло «стадия „limited_sales“ —
самоотчёт извлекателя». Оговорка подсказку не снимала, потому что человек решает ровно тот
же вопрос. Вместо неё: «стадию определите сами по тексту источника: наша оценка стадии в
карточке не показана намеренно».

### 2. Несовместимость формы с их проверяющим скриптом — найдена синтетическим циклом

Экспорт из первой версии формы их скрипт отбросил бы **целиком**: `invalid_reviews`,
принято 0 из 30. Причины в `weakness_binary.py:130–160`: требуется `label_source ==
"human_review"` (форма писала `"human"`), непустой `source_ids` из числа источников
карточки, и для `weak`/`mature` обязательны `facts_checked` и `stage_checked`.

Форма исправлена: пишет `human_review`, не даёт сохранить решение без отмеченного
источника, для `weak`/`mature` требует обе галочки. Повторная синтетическая проверка:
**принято 30 из 30, `issues: []`**. Синтетический файл удалён, в пакет не попадал,
меток от имени Марины и Олега не создавалось.

### 3. Даты события и публикации разделены

Подтверждён случай из разбора: `github.com/requie/LLMSecurityGuide`, две записи с
`date = 2025-12-10` при `published_at = null` у документа — дата пришла из `event_date`
кандидата. В v2 этой подстановки нет:

| поле | содержание |
|---|---|
| `date` | только `published_at` документа; иначе `null` |
| `date_origin` | `document_metadata` или `unknown` |
| `event_date_claimed` | дата события из извлечения, отдельно |
| `event_date_origin` | `extractor_from_quote_unverified` |

Тот же случай в v2: `date = null`, `date_origin = unknown`,
`event_date_claimed = 2025-12-10 (extractor_from_quote_unverified)`.

Источник с датой публикации **позже среза** больше не обнуляется, а исключается целиком:
обнуление обходило календарный валидатор, оставляя знание из будущего. В этих 30 таких
источников не оказалось (счётчик `исключено_источник_после_среза = 0`), ветка исправлена
на будущее. В признаки модели (`feature_text`) идут только `date` и `summary_ru`, поэтому
`event_date_claimed` на обучение не влияет и остаётся видимым человеку.

### 4. Проверка цитаты перенесена в сборщик

Codex подтвердил вручную 43/43 совпадения цитат с текстом снимка, но в коде проверки не
было — пакет мог уехать с непроверенной цитатой. Теперь сборщик находит цитату в тексте
документа и хранит `quote_start`, `quote_end`, `document_sha256`; не найдено — источник
не берётся. На этих данных исключено 0, то есть 43/43 воспроизведены программно.

### 5. Семейства больше не выдуманные

В v1 `family` = первые два слова названия: «обнаружение-и», «аудит-и». Ключ выглядел как
проверенное семейство и ничего не значил. В v2 `family = fam-<хеш8>` — нейтральный
идентификатор, который ничего не утверждает, а предполагаемые семейства вынесены в
`families-to-review.md`: 47 групп карточек с общими значимыми словами названия или
механизма, без меток, на ручную сверку. **До этой сверки разделение train/test
считается предварительным.**

## Что обучением этого пакета сделать нельзя

Проверено их же скриптом на синтетических метках: при 20 обучающих карточках требование
`need_12_reviewed_train_examples_per_class` (12 weak + 12 mature = 24) недостижимо при
любой разметке. Даже всё разделение из 30 не даёт 24 + 10. Порог не ослабляем.

Отсюда единственное корректное применение: **диагностика переноса** — обучение на их
пилоте из 60, оценка на этих 30 после независимой человеческой разметки. `train`-часть
нашего split в таком опыте для подгонки не использовать; она остаётся техническим
артефактом. Режима внешней оценки замороженной модели в их CLI сейчас нет — совместимость
формата его не заменяет.

`unknown` показывать отдельно: число, причины, доля от всех 30. Не прятать в знаменателе
и не превращать в `mature`. Обзор, SEO-подборка и неизвестная стадия сами по себе
зрелость не означают.

## Что остаётся неустановленным

Стиль составителя: у их карточек `summary_ru` — пересказ куратора, у наших — модели по
снимку. `provenance_role` внутри одного пакета константа, поэтому как контроль он работает
только в объединении, и Codex прав, что одного этого признака недостаточно. Полезнее
раздельная оценка по происхождению и отдельная проверка предсказуемости происхождения по
тексту — она тоже показывает различимость, а не автоматически вред.

Обозначения primary/secondary — эвристика по домену из `radar/hoststats.py`, содержательно
по каждому источнику не проверены. Истинность рыночных утверждений в карточках не
установлена: проверена только точность цитирования сохранённого снимка.

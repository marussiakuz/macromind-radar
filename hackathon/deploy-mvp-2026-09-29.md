# Развёртывание на публичном сервере

Для локального запуска используйте [README](../README.md). Этот вариант добавляет HTTPS к тому же приложению; отдельный сайт и предварительная ручная сборка интерфейса не нужны.

## Новая установка

Нужны Linux-сервер с Docker Engine и Compose v2, домен с DNS-записью на этот сервер и открытые входящие порты 80/443. Порт API 8000 публикуется только на loopback сервера. Caddy обращается к приложению по внутренней сети Docker.

1. Клонируйте репозиторий и перейдите в его корень.
2. Выполните `cp .env.example .env`.
3. Укажите в `.env` `RADAR_HOST=radar.example.org`, заменив пример своим доменом. Для начала оставьте `RADAR_DEMO=1`.
4. Запустите:

   ```bash
   docker compose -f docker-compose.yml -f hackathon/docker-compose.yml up -d --build
   ```

Caddy получает сертификат автоматически, если домен указывает на сервер и порты доступны. Откройте `https://ваш-домен` и проверьте сохранённый Edge-пример. Дополнительно проверьте `https://ваш-домен/api/health`.

Скрипт `bash hackathon/deploy/remote-setup.sh` выполняет эту же сборку и запуск. Он не устанавливает Docker и не копирует старое состояние.

## Новый анализ

Настройте ключи, модель, квоты и `RADAR_PUBLIC_TOKEN` по [документации](../DOCUMENTATION.md), установите `RADAR_DEMO=0` и пересоздайте контейнеры той же командой с двумя compose-файлами. Задайте лимиты расходов через `python -m radar.ledger topup` внутри контейнера.

Токен защищает запуск, но чтение результатов остаётся открытым. Для конфиденциальных запросов ограничьте доступ к приложению на уровне сети или добавьте полноценную аутентификацию перед ним. Не публикуйте backend отдельно от прокси: конфигурация для HTTPS доверяет заголовкам внутреннего прокси.

## Обновление и диагностика

Из корня репозитория:

```bash
git pull --ff-only
docker compose -f docker-compose.yml -f hackathon/docker-compose.yml up -d --build
docker compose -f docker-compose.yml -f hackathon/docker-compose.yml ps
docker compose -f docker-compose.yml -f hackathon/docker-compose.yml logs --tail=100
```

Обновляйте сервис между анализами: задачи в памяти при перезапуске теряются. Том с результатами и расходами сохраняется. Перед миграцией сделайте резервную копию этого тома и `.env`.

**Для ранее развёрнутой VM:** новая конфигурация рассчитана на полный репозиторий и именованный том. Старые bind-mount каталоги и бюджет автоматически не переносятся. Сначала перенесите существующий `radar-runs` и проверьте владельца файлов (UID 1000). Не создавайте новый журнал вместо действующего. Эти изменения сами по себе не обновляют публичный прототип.

`deploy/pack-runs.py` может собрать архив готовых разборов. По умолчанию бюджет туда не включается; `--include-ledger` предназначен только для переноса состояния своей установки. Такой архив не является полной резервной копией исходных документов.

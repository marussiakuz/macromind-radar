## Новые вводные из QA-сессии с заказчиком, 17.09 — важнее ТЗ там, где они расходятся

Расшифровка: `hackathon/Документы от заказчика/Бизнес 1. Газпромбанк Тех.md`. Прочитай её перед разделами 4–6 и пересмотри предложения П-01…П-13 с учётом этих фактов.

- Отдельного размеченного датасета нет. Таблица из 100 технологий — это и есть обучающие данные, в ней только положительные примеры. Отрицательных примеров заказчик не давал, «может подумать». Дополнять данные своими примерами разрешено.
- Целевую переменную выбирает команда. Балл и стадия не важны.
- Проверка — живые открытые запросы. Порог 75 % — это доля позиций из первых 15, с которыми согласны эксперты, то есть не меньше 12 из 15. Выше 80 % — лучше. Метрику для отчёта команда выбирает сама и обосновывает.
- Шесть областей из таблицы проверят точно, финтех — точно, дальше — любое направление: например, 3D-печать, микрофлюидный чип, «гардрейлы» ИИ, приоритеты «Приоритет-2030». По шести областям ожидают увидеть технологии из таблицы. Не попавшее в таблицу по этим темам эксперты считают хайпом или шумом. По другим направлениям каждую позицию оценивают голосованием экспертов. Совпадение — по смыслу, не по буквам.
- В каждой области таблицы 16–17 технологий. Значит, для 12 верных из 15 система должна найти 71–75 % списка области.
- Если сигналов меньше 15, считают долю верных среди выведенных.
- Если порог не пройден, обоснование не важно. Если пройден, смотрят источники, кейсы и полноту.
- Отсеянные экспертами технологии отбрасывались из-за больших инвестиций, большого числа упоминаний и большого числа компаний.
- Время живого запроса — до ≈20 минут, частичная выдача допустима.
- Зарубежные источники нужны: сигнал может ещё не существовать в России. Название технологии — по-русски, допустима транслитерация. Crunchbase, поисковые API и агрегаторы новостей разрешены при ссылке на первоисточник, но нужен отечественный или резервный вариант.
- Любые LLM и API разрешены, но заказчик может проверить, насколько падает качество при замене модели.
- Признаки, по которым технология отнесена к сигналу, показывать нужно. Вклад каждого признака не важен. Источники очень важны. Список доверенных источников команда составляет сама, eLibrary — доверенный. Противоречия источников должны влиять на уверенность.
- Не важны: авторизация, история, фирменный стиль. Список исключённых — плюс, без обязательной детализации. ETL — плюс, не обязателен.

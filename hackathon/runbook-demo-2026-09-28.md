# Runbook живого показа и результаты репетиции

28.09.2026. Порядок запуска для защиты, проверенные крайние случаи и список дефектов,
найденных репетицией. Дефекты разделены на исправленные и оставшиеся.

## 1. Запуск за пять минут до показа

```sh
cd "hackathon" && .venv/bin/python -m radar.server          # сервис, 127.0.0.1:8000
cd "tech-trend-searcher" && npm run dev                     # интерфейс, порт печатается в консоль
curl -s http://127.0.0.1:8000/api/health                    # {"ok":true,"demo":false,"runs":N}
```

Проверить перед жюри: `health` отвечает `ok:true`; `demo:false` (в демонстрационном режиме
живой запрос невозможен); в `runs` не ноль — значит сохранённые прогоны на месте.

Если сеть на площадке не работает: `RADAR_DEMO=1 .venv/bin/python -m radar.server` —
сервис отдаёт только сохранённые прогоны и честно об этом сообщает.

## 2. Сценарий показа

1. **Запрос, который отвечает за секунду.** «слабые сигналы в финансовых технологиях» или
   «слабые сигналы в защите искусственного интеллекта» — по ним есть разобранный прогон,
   ответ приходит за 1 с, на странице написано «показан сохранённый разбор». Это открытие
   показа: список, объяснения, цитаты, компании.
2. **Разбор одной позиции.** Открыть карточку: механизм, баллы из окна зрелости с
   расшифровкой каждого признака, дословная цитата со ссылкой, блок «Кто это делает» с
   ролями компаний. Ссылку открыть при жюри — она живая.
3. **Список отбракованных.** Страница «Исключённые»: причина по каждой позиции, с числами
   («масштабировано и громко: 195 494 упоминаний»). Это ответ на вопрос «а вы уверены, что
   не выдаёте мейнстрим».
4. **Открытый запрос от жюри.** Любая формулировка вне таблицы — живой прогон 7–11 минут.
   Предупредить о времени заранее и в это время показывать § 3 и методологию.
5. **Отказ и нехватка данных.** Показать позицию уровня «требует проверки» с текстом
   причины: «громко: проверить уровень термина», «термину 12 лет: проверьте, не старое ли
   это понятие», «зрелость не измерена». Это сильная часть, а не слабая: система не
   притворяется уверенной.

## 3. Что проверено на репетиции

| Проверка | Результат |
|---|---|
| Ключи в сборке интерфейса | `dist/` не содержит `YANDEX_API_KEY`, `OPENALEX_API_KEY`, `folder_id`, токенов |
| `.env` рядом с интерфейсом | отсутствует; ключи только на стороне сервиса |
| Запрос короче трёх символов | 400 с текстом причины |
| Несуществующая задача | 404 |
| Повторный запрос | 1 с, без расходов, помечен как сохранённый разбор |
| Ссылки в карточках и у компаний | 6 из 6 проверенных отвечают 200 |
| Сервис недоступен | интерфейс показывает последний сохранённый прогон и сообщает об этом |
| Тесты | 48 проходили на репетиции 28.09; на 29.09 их 102 |

## 4. Дефекты, найденные репетицией и исправленные

1. **Термины 1964, 1977 и 2000 года стояли в верхних позициях «Защиты ИИ»** как ранние
   сигналы, с 4 147 и 19 560 упоминаний. Две причины: область для нормировки измерялась
   по запросу со словами нашей задачи, из-за чего модель вернула «signal processing» и
   объём области 1 041 032 работы (порог громкости раздулся в 46 раз), и правило возраста
   термина в переписанном `rank.py` отсутствовало. Исправлено: область спрашивается без
   слов задачи, нормировка ограничена восьмикратным p90 эталона, добавлены возрастные
   ворота (старое и громкое — отказ, старое и тихое — к проверке), балл больше не
   перебивает пометки замера. Уверенных позиций стало 6 вместо 13.
2. **Повторный запрос пересчитывал карточки заново**: 4–5 минут и платные вызовы модели на
   уже посчитанном пуле. Для показа это риск. Добавлен кеш разобранных карточек рядом с
   прогоном, с версией: 1 с и 0 ₽. При правке оценки версия поднимается, иначе показ
   отдал бы устаревший результат как новый.
3. **Страница прогресса обещала «без новых расходов»** и в том случае, когда из
   сохранённого брался только пул документов, а оценка считалась заново. Теперь три
   честных состояния: сохранённый разбор, сохранённый пул, живой прогон.
4. **Блок «Кейс-пример» был пустым на всех 15 карточках** — отдельного утверждения «Кейс»
   извлекатель не формирует. Теперь кейс — дословная цитата источника со ссылкой и
   перечислением найденных компаний: именно то, что требует заказчик.
5. **Балл 11,5 при подписи «из 11»** — потолок был константой, хотя надбавки за
   подтверждение с разных доменов и найденных реализаторов выводят балл выше. Потолок
   считается по факту.
6. **Счётчик «уверенных» считался до поиска компаний** и расходился с тем, что видно на
   экране: 4 против 6. Пересчитывается после.

## 5. Дефекты, оставшиеся к показу

1. **Нет серверного ограничения на длительность прогона.** Если поисковый API зависнет,
   задача останется в состоянии «выполняется», а интерфейс будет опрашивать её без конца.
   Обход на показе: открытый запрос от жюри запускать не позднее чем за 12 минут до конца
   слота, держать наготове сохранённый прогон.
2. **Первое упоминание термина иногда абсурдно старое** (фразовое совпадение в статье
   1996 года). Позиция теперь не может стать уверенной, но дата видна в карточке, и это
   вызовет вопрос. Ответ по существу: это измерение по индексу, а не утверждение о
   технологии, поэтому позиция помечена «требует проверки».
3. **Проверка принадлежности области несогласована** — она снижает балл и помечает
   позицию, но не отбрасывает. На «Финтехе» помечает 26 кандидатов из 96.
4. **Четыре области из шести живьём не прогонялись**, человеческой валидации нет ни по
   одной позиции.
5. **Разброс между повторами ±2 позиции** — при повторном показе того же запроса на живом
   прогоне список будет отличаться. Для показа использовать сохранённый разбор.

## 6. Если что-то сломалось при жюри

| Симптом | Действие |
|---|---|
| Интерфейс пуст, сервис не отвечает | перезапустить сервис; интерфейс сам покажет сохранённый прогон |
| Живой прогон идёт больше 12 минут | открыть сохранённый разбор по близкому запросу и сказать об этом прямо |
| Поисковый API отвечает отказом | перейти на `RADAR_DEMO=1` и показывать сохранённые прогоны |
| Вопрос «почему позиций меньше 15» | условие задачи это допускает; порог согласия 75 % важнее длины списка |

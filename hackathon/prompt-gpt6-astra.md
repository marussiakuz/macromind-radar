## Что предлагает Claude (проверь каждый пункт)

- **C1. Позиционирование.** Прозрачная формула + каждое утверждение со ссылкой + ретро-проверка «как будто 2019 → что выросло к 2024» вместо «LLM, назови 15 трендов». Главный российский аналог — iFORA (ИСИЭЗ ВШЭ).
- **C2. Определение тренда.** Пять признаков зарождающейся технологии по Rotolo, Hicks, Martin (2015) и квадранты слабых сигналов по Yoon (2012): малая видимость и высокий рост.
- **C3. Метки.** Тема с первым упоминанием в году t0 ∈ [2010; 2018] получает 1, если к t0 + 5 у неё не меньше N публикаций в год и доля в направлении не ниже X %; иначе 0. N и X подбираются по кривым известных технологий и проверяются на эталонных списках: 40–60 выросших и 40–60 заглохших технологий.
- **C4. Время.** Обучение — когорты 2010–2014, валидация — 2015–2016 (подбор параметров и порогов), отложенная когорта — 2017–2018 (запускается один раз в конце, итоговые цифры — только с неё), прогноз — темы 2021–2025. Признаки считаются только по данным до года T. Подбор может вести Codex по цели `/goal` «precision@15 на валидации ≥ база + X п.п.»; отложенную когорту запускает человек.
- **C5. Кандидаты.** LLM разворачивает направление в 15–30 подтем на русском и английском → ключевые фразы KeyBERT и ключевые слова OpenAlex (BERTopic — если останется время) → LLM-фильтр «это технология?» → склейка синонимов. Цель — не меньше 80 % технологий из эталонного списка среди кандидатов.
- **C6. Признаки (≈15–20 на пару «тема × год»).** Год первого упоминания; публикации за T, T−1, T−2; рост за 1 и 3 года; ускорение; доля в направлении; число организаций и групп; доля компаний; число стран; международное соавторство; уровень изданий; доля препринтов; скорость цитирования; доля цитат из других областей; патенты, если подключён Lens.
- **C7. Модель.** LightGBM (binary или lambdarank) + SHAP. Соперник — формула «рост × новизна × разнообразие организаций». Метрика — precision@15 и recall@15: подбор — на валидации, итог — на отложенной когорте. План Б: если модель не лучше формулы, идём с формулой и показываем честное сравнение.
- **C8. LLM.** Только инструмент (синонимы, фильтр, карточки через RAG со ссылками), не предсказатель. Qwen3.6-35B-A3B (MoE, ≈3B активных параметров, ≈37 ГБ в FP8) или плотная Qwen3.6-27B; эмбеддинги bge-m3; сервинг — vLLM со структурированным выводом по JSON-схеме. Дообучение LLM на хакатоне не планируется.
- **C9. Сервер.** Для хакатона: 1 × GPU 48 ГБ (L40S или RTX A6000), 16–24 vCPU, 64–128 ГБ RAM, 1 ТБ NVMe. Новое требование команды — задел под возможное дообучение Qwen ≈30B. Под него Claude предлагает 1 × GPU 80 ГБ (H100 или A100 80 ГБ), 24–32 vCPU, 128–192 ГБ RAM, 2 ТБ NVMe: QLoRA для 35B-A3B и 27B, LoRA в bf16 для 27B — на пределе. Полное дообучение 30B (≈480 ГБ видеопамяти, 8 × 80 ГБ) не нужно. Бюджетный вариант — 48 ГБ.
- **C10. Данные.** OpenAlex (с 13.02.2026 обязателен ключ; бесплатно $1 в день на ключ ≈ 10 000 запросов с фильтрами или 1 000 поисковых; есть бесплатный снапшот CC0 на S3), arXiv, Lens (патенты, токен по запросу), GitHub — по возможности.
- **C11. Архитектура.** Пакетно: источники → PostgreSQL + pgvector → кандидаты → признаки → обучение. По запросу: направление → подтемы → корпус → кандидаты → оценка → ТОП-15 → карточки RAG → интерфейс. FastAPI, фоновая очередь, Streamlit, docker-compose (api, worker, postgres, vllm, ui). API: `POST /analyze`, `GET /tasks/{id}`, `GET /trends/{id}`, `GET /health`.
- **C12. Черновик таблиц БД.** works, authors, institutions, sources, patents, term_mentions, candidates, features (тема × год), analyses, trends, cards, citations, feedback, shortlist.
- **C13. Сценарий пользователя.** Основная роль — аналитик технологической разведки банка (ещё — владелец продукта и инвестиционный менеджер). Принцип: за 15 минут от направления до шорт-листа, каждый тренд проверяется по первоисточнику. Семь шагов: вход и история → уточнение подтем с предупреждением «слишком широко / узко» → запуск и прогресс (новое направление — до 30 минут, из кэша — секунды) → ТОП-15 (таблица и карта квадрантов, дата данных) → карточка (почему в топе, мотивация, эволюция позиционирования, кейс, источники; «источник не найден» вместо догадки) → шорт-лист и «Не релевантно» → выгрузка PPTX или PDF.
- **C14. Порядок работ.** У Марины 9 задач строго по очереди с 13 по 28.09: сервер, методология, корпус, кандидаты, признаки, модель, ТОП-15, карточки, сборка. У Олега 5 задач: регламент, эталонные списки и ручные проверки, макет и JSON-контракт, интерфейс, питч. Контрольные точки: 14, 16, 17, 18, 19, 21, 23 (модель или план Б), 26 (фича-фриз), 28 (генеральный прогон), 29 (сдача). Порядок сокращения объёма: позиционирование как признак → патенты → BERTopic → шорт-лист → карта квадрантов → третье направление.
- **C15. Демо, 3 минуты.** Готовое направление «технологии в ИИ» → карточка с открытием первоисточника → ретро-проверка → второе направление → выгрузка и встраивание по API.

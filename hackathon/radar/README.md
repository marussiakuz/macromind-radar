# Радар: вертикаль «направление → пул кандидатов»

Прототип проверяет один вопрос: **сколько эталонных категорий области доходит до пула кандидатов**.
Фильтра зрелости, карточек, интерфейса и базы данных здесь нет — они в разделе 14
`review-full-lct-2026.md`. Решения по сбору — `review-sources-pipeline.md`.

## Запуск

```bash
cd "hackathon"
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install pytest
.venv/bin/python -m pytest radar/tests -q          # 26 тестов, сеть не нужна

.venv/bin/python -m radar reference                # эталон из таблицы заказчика
.venv/bin/python -m radar dry-run --area "Защита ИИ"   # сколько будет стоить живой прогон
.venv/bin/python -m radar run --area "Защита ИИ" \
    --direction "слабые сигналы в защите искусственного интеллекта" --mode fixtures
.venv/bin/python -m radar evaluate --run radar-runs/<run_id>
```

Живой прогон — тот же `run` с `--mode live` и переменными окружения:

```bash
export YANDEX_API_KEY=...      # ключ сервисного аккаунта
export YANDEX_FOLDER_ID=...    # каталог Yandex Cloud
```

## Что считается

`C` — число разных эталонных категорий области, найденных в пуле. Машина только **предлагает**
пары «кандидат — строка эталона» в `matches.json`. Засчитывает их человек: правит `decision`
на `accepted` или `rejected` и запускает `evaluate`. Так метрика не подстраивается под выдачу.

Цель по разделу 14 — `C ≥ 14` при 16–17 категориях в области.

## Что уже защищено тестами

- Загрузчик отказывает внутренним адресам, `file://`, портам вне 80 и 443 и логину в URL;
  каждый редирект проверяется заново.
- Запрет в `robots.txt` — это статус ответа, а не повод сменить User-Agent.
- Кандидат без цитаты, найденной дословно в своём фрагменте, отбрасывается.
- Инструкция внутри загруженной страницы не создаёт кандидата: текст документа — данные.
- Соседние категории таблицы (№67 и №69) не склеиваются, переводы одного названия — склеиваются.
- `C` считается один к одному: два кандидата не закрывают одну строку эталона дважды.

## Чего ещё нет

- Параллельности: этапы идут последовательно, поэтому время прогона пока не показатель.
- PDF, JavaScript-страниц, OCR — только HTML.
- Кэша поиска и снимков между прогонами, фонового ETL, arXiv и OpenAlex.
- Пининга IP на соединение: между проверкой DNS и запросом адрес теоретически может смениться.
- Адаптеры Yandex Search API и Yandex AI Studio написаны по документации и **не проверены живым
  вызовом**: состав запроса и разбор ответа нужно подтвердить на первом запуске с ключами.

## Артефакты прогона

`radar-runs/<run_id>/`: `manifest.json` (версии, лимиты, счётчики, стоимость), `hits.jsonl`,
`fetches.jsonl` (включая отказы и их причины), `documents.jsonl`, `candidates.jsonl`,
`matches.json` (для подтверждения человеком), `report.txt` (воронка потерь).

Материалы заказчика и выгруженный эталон не публикуем: `radar/eval/` и `radar-runs/` держим вне
открытого репозитория.
